# 国内外市场结论与产品取舍

**检索基准：2026-10-08。** 收录国内8个、国外10个产品/系统条目，含直接竞品、平台型与相邻工具，不能统称18个“刑侦Agent”。另核实公开采购/部署证据。公开检索并非穷尽；没有试用、真实卷宗测评或专业访谈。

## 1. 结论

**方向真实，但不是空白市场；“卷宗RAG + 时间线 + 图谱”本身不够构成竞争优势。**

- 国内既有早期规则/NLP体系，也有公安自建的本地大模型工作流。上海“206”、TRS和昆山笔录系统覆盖了材料/证据核对的不同环节。
- 国外Cellebrite Genesis、Guardian Investigate、Magnet Review Intelligent Insights、Penlink CoAnalyst已明确提供调查问答/摘要/工作流；部分官方页面主张时间线、关系分析、矛盾提示和来源回链。
- 采购需求确实存在，但新AI模块成熟度、独立效果、中文能力、完整离线交付与价格，公开证据不足，不能按市场空白或宣传指标估算商机。

## 4. 哪些地方有机会，哪些只是自我安慰

### 不够的卖点

“我们也能聊天”“用了多Agent”“能生成关系图”“换一个更大模型”“私有部署”——都不能单独证明比现有系统好。离线、引用、人审甚至可能是准入底线，而不是创新。

### 值得验证的差异化假设

1. **中文卷宗的原页复核成本更低**：每个陈述/事件/关系/差异可点到正确页、框、版本；不藏反证。
2. **差异可纠错而非武断**：同名、模糊时间、OCR误差、否定、转述分开处理；人审可撤销，反馈形成回归测试。
3. **不增重复录入**：从已有合法导出的材料进入，报告审核回到用户现有流程。
4. **权限与审批可以验收**：案件级授权贯穿检索、缓存、任务恢复、引用与导出；不是只在prompt里禁止。
5. **可交付、可替换**：批准的离线环境、本地模型、版本固定、测量资源，能够迁移/退出而不是被某API锁死。

上述都是待验证的产品假设，**不是已证明竞品没有这些功能**。

## 5. 给个人开发者的建议

先做“多份笔录的时间线整理与待核查差异”原型：材料→原页引用→检索→结构化抽取→规则+模型提出差异→人工审核。数据只用明确合成样本。

- 原型技术：Vue/TypeScript + FastAPI/Pydantic + PostgreSQL/pgvector + PaddleOCR + 可替换模型；需要时才引入LangGraph。
- 需求验证后，Java/Spring负责案件/权限/审计，Python负责OCR/检索/模型工作流；不要第一版就双后端、多数据库、多Agent。
- 真正To G试点需要专业使用者、合法测试资料、审批和交付能力；技术演示不能替代这些条件。

**对当前阶段最诚实的定位：有研究价值、有作品价值，商业可行性尚未验证；先验证窄任务，不建设“全警AI破案平台”。**
